# Qmanga — обновление продукта

Задачи из плана от 18 октября 2026 года перенесены в Backlog.md 19 октября 2026 года. Единственная очередь и статусы находятся в `backlog/tasks/`; этот файл хранит общие требования и порядок этапов.

## Работа с доской

```sh
bun install --frozen-lockfile
bun run backlog browser --no-open
bun run backlog task list --plain
bun run backlog task view TASK-3 --plain
```

Доска: <http://127.0.0.1:6420>. `Done` при переносе означает историческую отметку о проверке и выпуске из исходного UPDATE.md; повторной проверки серверов не проводилось. `Review` означает реализацию, для которой ещё остаётся приёмка или выпуск. Установка Backlog.md нужна для задач, но не для запуска самого сайта в Docker.

## Общий договор для всех этапов

1. Интерфейс работает на 320 и 360 px и на широком экране, на казахском и русском, в светлой и тёмной теме. Кнопки и пункты меню доступны клавиатурой, имеют видимый фокус и цель не меньше 44 px. Уважать `prefers-reduced-motion`.
2. Переходы, модальные окна и панели не скрывают работу с формой; закрываются по Escape, явной кнопке, а где уместно — по фону. Фокус возвращается к открывшей кнопке. Ошибка сервера остаётся видимой и не теряет введённый текст.
3. Оценки, просмотры, подписчики и графики используют только реальные данные с определённой методикой подсчёта. Пустые данные показываются как «пока нет данных», не как ноль там, где измерения вообще нет.
4. Изменения Go идут через домен → application → PostgreSQL/медиа → HTTP. Svelte показывает состояние и вызывает порты. Любые новые метрики и операции проходят проверку доступа на сервере.
5. Каждый этап заканчивается тестами уровня, который способен поймать его сбой, браузерной проверкой на 320/360/desktop, CI, тестовым доменом и только потом основным доменом. Миграции совместимы с работающим предыдущим релизом во время переключения.


## Порядок этапов

1. Безопасное редактирование у переводчика; ближайшая открытая задача — TASK-3, пошаговое создание главы.
2. Карточка тайтла, возрастная маркировка, статистика и обсуждение. Учёт просмотров — условная задача, сначала методика.
3. Каталог, категории и подборки.
4. Административная область, меню, уведомления и футер.
5. Аккаунты, аватары и библиотека.
6. Метрики и рабочие панели.
7. Google OAuth после настройки проекта владельца.
