Дата: 17 октября 2026 года. Статус: дорожная карта продукта до начала реализации. Технические задания по файлам и командам будут составлены после согласования спецификации. Сейчас не выбираются сервер, тариф и железо.

## В каком порядке проверять продукт

Каждый этап заканчивается работающим пользовательским сценарием. Переход к следующему основан на его проверке; календарный срок без состава команды и доступности переводов пока не фиксируется.

| Этап | Что появляется | Как принимаем |
| --- | --- | --- |
| 0. Согласование продукта | Границы MVP, словарь, мобильные схемы главной, тайтла, читалки и studio | Владелец проходит путь читателя и редактора на схемах 360 px; подтверждает приоритеты |
| 1. Сквозной путь одной главы | Один реальный разрешённый тайтл, одна команда, обработка изображений и публикация через минимальный служебный интерфейс | Гость с телефона открывает первую страницу; опубликованная версия целостна, исходник закрыт |
| 2. Читалка в плохих условиях | Лента и страницы, eco/standard/high, очередь, повторы, память, локальная позиция | На слабом Android проходят обрыв и длинная глава; записаны время, байты и наблюдения по памяти |
| 3. Каталог и тайтлы | Главная, поиск по названиям, фильтры, страницы тайтлов, список глав и команды | Новый читатель находит нужное и продолжает выбранный перевод без смены команды |
| 4. Личный путь читателя | Аккаунт, библиотека, прогресс между устройствами, уведомления, сохранённые главы | Вход возвращает к чтению; офлайн-копия открывается после перезапуска; конфликт прогресса решается явно |
| 5. Несколько команд | Мобильный studio, роли, приглашения, загрузки, порядок, предпросмотр и ревизии | Две команды публикуют одну логическую главу, не видят чужие черновики; телефон достаточен для всего процесса |
| 6. Общение и модерация | Комментарии, ответы, спойлеры, оценки, жалобы, очередь проверки и снятие | Проверены права, возврат с причиной, исправление опубликованного релиза и отсутствие дублей |
| 7. Закрытая бета и выпуск | Реальные переводы, полная языковая вычитка, исправления по использованию | Несколько читателей и редакторов проходят сценарии без помощи разработчика |

На этапе 1 временный служебный интерфейс — часть вертикального среза будущей публикации, а не публичный доступ к хранилищу. Его проверка прав нужна сразу. Полный пользовательский кабинет и удобство нескольких команд развиваются на этапе 5.

Нельзя отложить чтение на слабом устройстве до завершения всех социальных функций. Если после этапа 2 не достигнута приемлемая читаемость и стабильность, сначала исправляем этот сценарий.

## Что должно быть нарисовано до компонентов

Проектировать состояния на мобильном экране, затем расширять их на планшет и компьютер. Для каждого экрана нарисовать не только удачный результат, но и загрузку, отсутствие данных, ошибку и отсутствие сети там, где оно имеет смысл.

1. Главная нового читателя и возвращающегося читателя.
2. Каталог с результатами, пустым результатом и открытыми фильтрами.
3. Тайтл без глав, с одной командой и с несколькими переводами одной главы.
4. Читалка: меню скрыто/открыто, качество, переход по главам, ошибка изображения, нет сети.
5. Библиотека: пустая, читаю, новые главы, любимое и конфликт сохранения.
6. Сохранённые главы: прогресс, готовая, неполная, мало места и удаление копии.
7. Studio: выбор команды, черновик, частичная загрузка, порядок страниц, предпросмотр, возврат модератором.
8. Модерация с телефона: список, сравнение/просмотр ревизии, причина решения.

Первый дизайн показывает реальный пример казахского длинного названия, несколько дробных номеров глав, слабую сеть и длинный вебтун. Эти данные важнее декоративного баннера.

## Проверки по этапам

| Уровень | Самые важные проверки |
| --- | --- |
| Модель данных | Дробные номера, несколько переводов, ревизии, порядок страниц, инварианты статусов |
| API и PostgreSQL | Межкомандные запреты, повтор submit/publish, потеря соединения, конфликт версий |
| Обработка медиа | Неправильный формат, повреждённые файлы, огромные размеры, падение worker, повтор без дублей |
| Читалка | Место при смене качества, отмена запросов, заполнители, контроль окна декодирования |
| Локальное хранение | Неполная глава, квота, удаление браузером, обновление service worker и выход из аккаунта |
| Сквозной путь | Команда загрузила → модератор принял → гость нашёл → прочитал → продолжил |
| Mobile First | 320/360/390/412 px, клавиатура, кнопка Назад, доступность касанием и экранным диктором |
| Реальное устройство | Длинная глава, плохая сеть, возврат после переключения приложения, память |
| Казахский | Диакритика, переносы, названия, поисковые алиасы, терминология и письма |

Автотесты покрывают риски данных, прав, публикации и прогресса. Разборчивость рисунка, удобство касания и пригодность слабого Android проверяются живым использованием. Зелёная сборка сама по себе не подтверждает качество читалки.

## Критерии публичного выпуска

- Все 13 продуктовых критериев из основной спецификации выполнены или объём релиза явно пересогласован.
- Две независимые команды могут пройти публикацию и исправление; ни одна не получает доступ к чужим черновикам.
- Есть небольшой реальный каталог с разрешёнными материалами; описания и интерфейс вычитаны на казахском.
- Проверены обычная манга, цветная манхва и длинный вебтун на физическом слабом Android.
- Читатель понимает выбор качества, размер сохранения и причину сетевой ошибки.
- Ошибочная, снятая или пустая глава не создаёт бесконечный спиннер.
- Нет смешивания личных данных при выходе и входе другим аккаунтом на том же телефоне.
- Поддержка и модерация имеют понятный путь обработки жалобы и возврата публикации.

## Решения для ближайшего обсуждения

| Решение | Предлагаемая исходная позиция | Когда нужно подтвердить |
| --- | --- | --- |
| Письменность | Казахская кириллица, структура локализации готова к расширению | Перед визуальными макетами и словарём |
| Вход | Почта и пароль, гостевое чтение, подтверждение для участия | Перед этапом 4 |
| Публикация | Все ревизии проходят модератора, команды одобряются вручную | Перед интерфейсом studio |
| Контент первого релиза | Манга/манхва/маньхуа, без ранобэ, видео, платных и 18+ материалов | Перед наполнением и фильтрами |
| Переводы | Несколько команд на один тайтл, один ответственный team_id у релиза | Перед финализацией схемы данных |
| Устройство для приёмки | Реальный Android с 2 GB RAM и проверка Chrome 109 как технического минимума | До выбора библиотек читалки |
| Поставка MinIO | Сохранить S3-контракт; выбрать поддерживаемую поставку отдельно | До публичного выпуска |

Это предложения для конкретизации проекта, а не повод останавливать исследование или подготовку документов. Следующий продуктовый шаг после обсуждения спецификации — мобильные схемы ключевых экранов; затем подробный план реализации первого вертикального среза.
