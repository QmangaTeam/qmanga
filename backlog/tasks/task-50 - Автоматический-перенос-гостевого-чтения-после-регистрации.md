## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Одноразовое серверное разрешение с непрозрачной HttpOnly cookie браузера регистрации: хранить только хэш, привязать к реально созданному аккаунту (email и Google), срок 7 дней. Обычный вход/повторная регистрация существующего аккаунта разрешения не создают. Перенос в композиции приложения после входа; облачный прогресс при конфликте сохраняется, гостевая запись не удаляется. Подтверждение завершения с CSRF и expected-account; повтор/ошибка/смена аккаунта безопасны. С работающим переносом убрать ручной блок.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Исследование: CreateAccount при регистрации и создание Google-аккаунта должны предоставлять одноразовое право переноса. Одного глобального pending-флага мало: вход с другого устройства не должен потреблять данные устройства регистрации. Нужен локальный intent без пароля/токенов с привязкой к новой регистрации и серверному аккаунту; существующий аккаунт после попытки повторной регистрации не должен получить автоимпорт. При конфликте по умолчанию сохранять облако и гостевую запись, не отправлять advance поверх ненулевой версии.

Backend готов: migration 000029, атомарные разрешения для новой email/Google регистрации, непрозрачная HttpOnly cookie без почты/пароля, только хэш в БД; GET eligibility + CSRF/expected-account completion. Обычный вход/дубликат/другой аккаунт/просроченный receipt не дают импорт; повтор completion безопасен. Полный Go ./... green, отдельные новые PostgreSQL проверки и HTTP/application повторяются после уточнения идемпотентности. Frontend и browser-приёмка продолжаются; без выпуска.
