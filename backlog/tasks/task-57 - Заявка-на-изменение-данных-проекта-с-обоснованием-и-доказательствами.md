## Формулировка владельца — дословно

так же где такое что можно добавить категории и жанры и тп к проектам, надо добавить изменить данные о проекте и там обосновать и прислать нужные evidence что бы отправилось на модерацию

## Дополнительное описание

В кабинете проекта нужен вход «Изменить данные проекта». Участник предлагает изменения сведений, включая жанры и категории, пишет обоснование и прикладывает доказательства. Заявка поступает модератору; до одобрения публичные данные не заменяются. Модератор должен видеть текущие и предложенные значения, обоснование и evidence, затем одобрить или вернуть с причиной. Автор видит результат. Не давать команде прямое редактирование глобального каталога вместо модерационного процесса.

Открытые вопросы отправлены владельцу: изменения общей карточки тайтла или только конкретного перевода; форматы evidence (ссылки/изображения). Состав «и тп» также ещё не задан полностью. Сохранить исходную цитату и не выдавать предположения за утверждённые требования. При реализации сохранить права, историю решения и защиту от перезаписи более свежих данных.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Общий workflow изменений карточки: типизированные предлагаемые сведения + жанры/категории, обязательное обоснование и ссылки/изображения evidence. Приватные изображения до одобрения, ACL проекта/модератора, неизменяемая история решения. Версию основания вычислять хэшем актуальных редактируемых сведений/таксономии/изображений, чтобы поймать изменения даже без updated_at. Одобрение/отказ/уведомление автора транзакционны; при конфликте свежие данные не перезаписывать. Баннер и ручные обложки включены по уточнению владельца, TASK-58 использует этот workflow. Проверить участника/постороннего/модератора, MIME/лимиты/доступ к evidence, гонки и публичные медиа.

Предлагаемые поля: название/оригинальное название, описание, алиасы/авторы, тип, статусы, направление, сведения об издании, возрастная маркировка, жанры и категории. Служебные slug/listed/featured/demo сохраняются из текущего тайтла, не выдаются команде как административные переключатели. Для изображений action keep/replace/remove; файлы cover/banner/evidence хранятся приватно при заявке, публичен только выбранный одобренный cover/banner. Одобрение сверяет canonical snapshot hash (включая таксономию и изображения), затем применяет всё и пишет audit/решение/уведомление одной транзакцией. По старым прямым endpoints ручных обложек не применять изменения; перевести UI и регрессии на заявки.

Новая миграция добавит title_change_requests и приватные title_change_assets (purpose evidence/cover/banner), banner_asset_id в titles. Общий media adapter публикует только выбранный одобренный cover/banner; evidence остаётся под актуальным ACL проекта/модератора. Ручные cover-file/select-cover endpoints не должны применять изменения в обход заявки. Редактирование категорий и approval должны одинаково блокировать строку title, затем проверять snapshot/применять таксономию, чтобы избежать гонки с административным изменением.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Владелец подтвердил 19 октября: после модерации меняется общая карточка тайтла для всех команд; форматы доказательств — ссылки и изображения. Это согласованные требования, не предположения.

Дополнительное прямое уточнение владельца: «баннер и обложку через модерацию тоже». Ручная загрузка, замена, удаление и выбор страницы как обложки должны создавать заявку; старые прямые endpoints не должны обходить модерацию. До решения текущие изображения сохраняются.

Начат domain: типизированные предлагаемые сведения без административных переключателей, независимые evidence, keep/replace/remove для изображений, canonical snapshot hash с таксономией/обложкой/баннером. Domain regression сначала red, затем Go catalog/domain green. Workflow/хранение/HTTP/UI ещё не реализованы; старые прямые ручные cover endpoints будут закрыты при переводе UI на заявки до выпуска.

Добавлен application coordinator: ACL/версия/валидность проверяются до обработки байтов, изображения только обработанные WebP с разными пределами cover/banner/evidence, приватная загрузка до создания заявки, очистка отказавших загрузок с проверкой неизвестного commit-результата (не удалять возможно сохранённые изображения). Application tests red→green. ImageMagick ProcessArtwork добавляет banner 1600×800 и evidence 2000×3000/5MiB, сохраняет прежний cover 720×1200/25MiB; реальные PNG→WebP тесты и весь пакет imagemagick green. Схема/репозиторий/HTTP/UI/moderation ещё впереди.
