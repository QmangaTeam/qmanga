## Дополнительное описание

При ответе сохранить контекст читаемого комментария и не переносить пользователя к общему редактору вверху обсуждения. Расположение редактора выбрать при реализации так, чтобы не приходилось спускаться обратно для продолжения чтения. Это новое требование владельца заменяет старый пункт TASK-9 о редакторе вверху с фокусом; старый пункт не является основанием сохранить неудобное поведение.

Границы: сейчас задача только зафиксирована по просьбе владельца. Не менять смысл исходной цитаты; предположения и открытые вопросы не считать утверждёнными решениями.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Показывать единый редактор непосредственно у комментария/ответа, на который отвечают (и у редактируемого сообщения). Фокус после обновления DOM без scrollIntoView верхнего редактора. Сохранить контекст адресата, разметку, отмену и существующую отправку. Браузерная регрессия на длинном обсуждении проверяет позицию и вложенный редактор.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Единый редактор рендерится у выбранного корневого комментария или ответа, а не наверху обсуждения. Фокус после tick с preventScroll; контекст адресата, разметка, отмена и отправка сохранены. Браузерная регрессия на 20 синтетических комментариях и вложенном ответе прошла: редактор внутри выбранного треда, положение треда в viewport сохраняется, ввод и отмена работают. Изменение scrollY при исчезновении верхней формы само по себе не является прыжком — проверяется положение читаемого треда. Docker/Svelte/114 прикладных/33 SSR/границы/контраст прошли.
