# Local development and acceptance

This is a local alpha/beta workflow, not production deployment. Use Docker Desktop/Engine with Compose v2, Git and PowerShell 7 (`pwsh`) on Windows. Linux/macOS can use the shell setup; the smoke scripts require PowerShell 7 there too. No host Bun or PostgreSQL is required to start the app.

## New checkout, new data

From the repository root, with Docker running:

```powershell
./scripts/setup.ps1
docker compose --parallel 1 up -d --build --wait --wait-timeout 180
```

Linux/macOS:

```sh
sh scripts/setup.sh
docker compose --parallel 1 up -d --build --wait --wait-timeout 180
```

Open <http://localhost:8080>. Development mail is captured at <http://localhost:8025>, never delivered externally. The catalogue is initially empty; there are no built-in accounts or copyrighted demo images. `APP_ORIGIN` must exactly match the address used in the browser, including the port. Only gateway and local Mailpit ports are exposed.

API and worker use the same Alpine runtime build, named from the Compose project. Both declare that build and `pull_policy: build`; startup does not require a pre-existing `qmanga-api:latest`. `--parallel 1` limits Compose service concurrency, not every compiler/BuildKit operation. See the [Compose pull policy contract](https://docs.docker.com/reference/compose-file/services/#pull_policy).

## Existing data, missing env

**Do not generate replacement passwords against old volumes. Do not delete volumes to repair startup.** Setup now refuses to create an env when this Compose project already has volumes, and refuses to guess when Docker is unavailable. An existing env is preserved byte-for-byte.

Find the original ignored `.env` in the previous checkout or your private local backup and restore it locally. A Git clone intentionally does not contain it. Keep the original PostgreSQL password, MinIO credentials and application secrets together; `.env.example` is not a recovery file. An audit's isolated env belongs to its own project, not the original database. Changing the PostgreSQL environment variable does not change an existing database password.

If the original credentials cannot be recovered, leave those volumes untouched and create a separate empty environment while arranging recovery. Example:

```powershell
./scripts/setup.ps1 -ProjectName qmanga-sandbox -EnvFile tmp/sandbox/.env -AppPort 18080 -MailpitPort 18025
docker compose --env-file tmp/sandbox/.env --parallel 1 up -d --build --wait --wait-timeout 180
```

Open <http://localhost:18080>; mail is at <http://localhost:18025>. The generated env includes `COMPOSE_PROJECT_NAME`, so every following command must use that same `--env-file`. No `-p` is necessary; if supplied, it must match. Never reuse a project name with different credentials. Shell setup supports `COMPOSE_PROJECT_NAME` and `QMANGA_ENV_FILE`; create the destination parent directory first and edit `APP_PORT`, `APP_ORIGIN` and `MAILPIT_PORT` together for alternate ports.

## Checks and a permitted synthetic publication

The commands below assume the default `.env`, ports and project. For another environment, add its `--env-file` to every Compose command and pass the same `-EnvFile`, `-ProjectName`, `-AppUrl` and `-MailboxUrl` to publishing and reading. Auth smoke accepts the two URLs. Do not run these tools against real user content: they create persistent disposable accounts, teams, titles and publications.

```powershell
./scripts/test-setup.ps1
./scripts/check-compose.ps1
docker compose --profile tools run --rm go-tests go test ./... -count=1 -json > tmp-go-tests.jsonl
if ($LASTEXITCODE -ne 0) { throw 'Go tests failed' }
$events = Get-Content tmp-go-tests.jsonl | ForEach-Object { $_ | ConvertFrom-Json }
if (@($events | Where-Object { $_.Action -eq 'skip' -and $_.Test }).Count) { throw 'Integration/codec check skipped' }
./scripts/smoke-auth.ps1
go run scripts/create-smoke-pages.go tmp/acceptance/pages
./scripts/smoke-publishing.ps1 -SourceDirectory tmp/acceptance/pages -PageLimit 3 -ConfirmRights -SourceNote 'Synthetic geometric pages generated by scripts/create-smoke-pages.go; no third-party artwork.' -Credits 'Qmanga acceptance tooling' -ResultFile tmp/acceptance/fixture.json
$fixture = Get-Content tmp/acceptance/fixture.json -Raw | ConvertFrom-Json
./scripts/smoke-reading.ps1 -ReleaseId $fixture.release_id
```

The generator uses only the Go standard library (host Go is needed for this check). Publishing first asserts that missing rights confirmation is rejected with 409, then stores attribution, reloads its new version, submits, moderates and checks actual WebP bytes/checksums through Go. `-ConfirmRights` is an explicit operator assertion, not inferred from the existence of an image file. With other permitted images supply truthful source/credits. `ResultFile` is optional and accepted only in a Git-ignored path: it contains disposable test credentials and must not be shared or committed.

The tools image provides PostgreSQL and ImageMagick integration prerequisites. A bare host `go -C backend test ./...` skips these without `TEST_DATABASE_URL`/codecs; that is not release acceptance. Go JSON events with `Action=skip` but no `Test` denote packages with no test files, not skipped integration tests; CI reports these separately. The web image build runs frontend application/adapter tests, Svelte SSR contracts, boundary and contrast checks, both Svelte checks and the production build. SSR contracts do not execute browser interactions.

## Browser regression

Install the locked frontend dependencies using Bun in `apps/web` (`bun install --frozen-lockfile`). Node 22 and Chromium are development-test tools only; the app still runs on Bun. Install a test Chromium using `node node_modules/playwright/cli.js install chromium` (Linux CI uses `--with-deps`), or set `QMANGA_BROWSER_EXECUTABLE` to an installed compatible Chrome. See [Playwright's CI prerequisites](https://playwright.dev/docs/ci).

From `apps/web`, with the fixture above:

```powershell
$env:QMANGA_FIXTURE_FILE = (Resolve-Path ../../tmp/acceptance/fixture.json).Path
node --test --test-concurrency=1 tests/browser/*.test.mjs
```

Run browser files serially against the shared disposable API. Parallel files can exhaust its real 30-authentication-requests-per-minute per-IP limit and contend for browser/worker resources. CI recreates the same API image after smoke fixtures and before this serial phase; persistent sessions, PostgreSQL data and private media are retained. Do not raise the production limit or bypass real login to accommodate tests.

Missing fixture values fail the run; they are not skips. The browser uses a new profile with real API authentication, follows the actual admin catalogue project link, and verifies that load/selection do not claim a write. It confirms persistence after saving, and injects one failed write at the HTTP boundary to verify error feedback and retained input. It must run only against a disposable local environment. This small suite is not coverage for the remaining library/offline/long-reader backlog.

## Administrative project policy

`/admin/projects/{id}` and `GET /api/v1/admin/projects/{id}` are admin-only, read-only context cards with title, team, status and links to catalogue editing/moderation. They do not grant membership or permit uploads, chapter creation or submission. Moderators continue to use `/moderation` and its existing review permissions. Studio remains team-scoped: owner/editor/member keep their own roles; a member is not an editor. Blocked/unverified accounts cannot use the staff read contract.

## Isolated comment/reply preview

For presentation review without signing in or writing to the local manga library:

```sh
bun --cwd apps/web ./node_modules/vite/bin/vite.js --config tests/community-preview/community-preview.config.ts
```

Open <http://localhost:3002/?locale=ru> or use `locale=kk`; add `theme=light` for the light palette. This fixture mounts the real discussion component with synthetic comments and an in-memory gateway. Submit/edit/remove/report actions affect only the preview state and reset on reload. The browser regression starts and cleans up its own random-port instance; the manual preview can remain running separately.

## Stop, resume and inspect

```powershell
docker compose ps
docker compose logs --tail 60 api worker web gateway
docker compose down --remove-orphans
```

`down` preserves volumes. Resume with the same env and startup command. Do not use `down -v`, a volume prune, or a new env as a routine recovery instruction. Keep the optional `web-ui` preview stopped when unused. Nothing in this workflow changes Docker Desktop/WSL global memory settings.

The [CI workflow](../.github/workflows/verify.yml) performs the build, integration, auth/publish/read and staff-browser checks on PRs, main pushes and manual runs. It uses fresh disposable data and fails on Go skips. Its configuration being present is not evidence that a remote run has passed; inspect the actual Actions result.
