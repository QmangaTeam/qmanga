# Importing prepared pages

The studio and authorized import tools use the same Go API. Import accepts prepared JPEG, PNG or WebP pages; it does not OCR, translate, typeset, unpack archives, or claim that machine output has been reviewed.

## Access and session

Use an authenticated verified account in an approved active project. Team members may upload; an editor or owner must submit. Moderator/admin approval is a separate action. Mutations use the existing session cookie and CSRF header from the normal identity flow; do not place either in a repository or logs. All source objects remain private. `/api/v1/media/:asset_id` streams derived images through Go and checks current access on every request. Original-tier images require project draft-read access even when the release is public.

## Repeatable import sequence

1. `POST /api/v1/studio/projects/{project}/revisions` with `{ "chapter_id": "..." }`. This returns the existing editable draft or creates a correction copied from the latest rejected/published revision, including ready pages, derivative records, source references, source note and credits. The public revision remains unchanged until moderation accepts the correction. A correction resets the human-review claim.
2. Read `GET /api/v1/studio/revisions/{revision}`. Keep its `version`, page IDs, `upload_key`, `position`, status, original filename and thumbnail ID. `release_status` describes public availability independently of the revision `state`.
3. For each prepared image, send binary bytes with `PUT /api/v1/studio/revisions/{revision}/pages?key={stable-key}&position={1-based-position}&name={URL-encoded-basename}` and `Content-Type: application/octet-stream`. Use a stable unique upload key of at most 128 characters for each logical file. A content SHA-256 is suitable. The server validates the actual image and checksum; repeated identical keys/bytes return the existing page rather than adding duplicates. Reusing a key with different bytes returns a conflict. Limits: 25 MiB/image, 80 MP/image, 300 pages and 500 MiB/revision. Use bounded/sequential uploads.
4. After interruption, fetch the revision, skip `ready`/`queued` keys, and resend only missing or failed transfers with their original key and position. A live transfer lease can return conflict; refetch and retry after the lease expires rather than creating a new key. For `processing_failed`, `POST /api/v1/studio/revisions/{revision}/pages/{page}/retry` retries the retained source without uploading it again. Browser retry retains files during the current visit; after reload the user reselects the same files. Source bytes are not persisted by the frontend to browser storage.
5. To replace a page safely, upload its replacement first at an unused last position with a distinct stable key. Once accepted, refetch. Send `PUT /api/v1/studio/revisions/{revision}/order` with `{ "version": CURRENT_VERSION, "page_ids": [ALL_RETAINED_PAGE_IDS_IN_ORDER] }`, substituting the uploaded page ID at the corrected slot. Omitted pages are deleted atomically from this draft. This leaves public images untouched. This safe upload-first method requires one spare page slot and enough temporary byte quota: replacement at 300 pages or near 500 MiB is not supported in one step. Retain the source locally, explicitly remove the target from the correction draft and save, then add the replacement; the published revision remains unchanged. The UI never deletes first automatically. A stale version returns 409 without deleting anything; refetch and reconcile intentionally. Do not blindly replay an old destructive list after a conflict.
6. Save `PUT /api/v1/studio/revisions/{revision}/attribution` with current `version`, `source_note`, `credits`, `rights_confirmed: true`, `preparation_method` (`unspecified`, `manual`, `machine_assisted`, or `machine`) and `human_reviewed` boolean. The latter is the team's attestation. The server records the authenticated reviewer and timestamp; it is not a moderator's certification of translation quality. Page changes clear the attestation. Invalid methods are rejected.
7. Poll the revision until every page is `ready`, inspect the authorized preview (`GET /api/v1/studio/revisions/{revision}/manifest` or `/read/{release}?preview={revision}`), then submit using `POST /api/v1/studio/revisions/{revision}/submit` with the latest `version`. Submitted and published revisions are immutable. A second submission is not treated as a new publication.

## Cover and availability

Ordinary studio artwork changes use the moderated title-change workflow; legacy `/cover` and `/cover-file` commands return `409 moderation_required` for session users and ordinary API tokens. A direct-publication administrator token may select a ready page from its editable project with `PUT /api/v1/studio/projects/{project}/cover` and `{ "page_id": "..." }`. It snapshots the first safe eco derivative in an independent cover record; the original remains private. Later chapter publication, draft-page removal and release withdrawal do not replace the chosen cover. Token selection is audited and rechecks current privileges atomically. Empty page IDs are rejected; arbitrary cover-file upload/removal through the privileged token path is not supported.

Moderators/admins may `POST /api/v1/moderation/releases/{release}/withdraw` or `/restore` with a nonempty `reason`. Restoration reopens the same accepted revision, not a newer draft. Both changes are audited with actor, reason and before/after availability. Withdrawal does not unlist an entire title or change the revision's published status. Separately moderated title listing remains separate.

## Headless administrator imports

See [the short Codex guide](CODEX-UPLOAD.md). Admins manage their own expiring, revocable API tokens at `/admin/api-tokens`. Raw secrets appear once; the database stores only hashes. Send `Authorization: Bearer ...`; scoped bearer requests do not need browser cookies, Origin or CSRF. Token management itself requires the ordinary administrator session and CSRF. Tokens cannot manage accounts, create more tokens, or use unrelated moderation/admin routes. The owner's current admin role, verification, block state and token expiry/revocation are checked on each authenticated request.

`python3 scripts/qmanga-upload.py --help` describes the dependency-free client. It inventories prepared image folders or CBZ/ZIP archives, naturally orders filenames, validates quotas before writes, uses per-position content keys, waits for processing and preserves a private state file for retries. It never deletes/reorders foreign draft pages or invents human review. Keep that state file; it is bound to account, site, manifest and page checksums. Source files are inspected locally; bearer tokens do not authenticate private draft image URLs.

A manifest may use `project_id` and `chapter_id`, or `project_id` plus `chapter: {label,order,volume,name}`. To create a title/project, use `team_id` plus `title_id` or `title` (the existing title creation JSON: slug,name,kind,original_status,translation_status,direction,description,listed,genre_ids,...). Choose an approved team the owner can edit. Existing slugs/projects/chapter orders are looked up before creation; conflicting chapter names/labels stop the import. For a public title set `listed:true`. Page processing must finish before publication. An optional `cover_page` is the 1-based uploaded page selected as project cover and requires the direct-publication token permission; ordinary browser artwork proposals remain moderated.

`--publish` calls `POST /api/v1/studio/revisions/{id}/publish` with `{ "version": CURRENT_VERSION }`. Only an administrator bearer token explicitly granted direct publication can use it. Authorization and token validity are rechecked under database locks; the ready revision is published atomically, without a persisted submitted state or moderation-queue notification. Ordinary publication events and audit records include the account and token identity. Retrying an already current published revision creates no duplicate events and never restores a withdrawn or superseded revision. `--submit` instead uses normal moderation; neither flag leaves a ready draft.
